# School Wars 重制方案

> 目标排序：① 原版玩法准确 → ② 可运行、可测试的最小版本 → ③ 让人玩得舒服（中文、存读档、画质、AI），**不靠增加系统复杂度**。
> 机制依据见 [01_原版机制考证.md](01_原版机制考证.md)。

## 1. 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | **TypeScript（strict）** | 原版是 AS1/2，与 JS 同源，逐函数移植时几乎能一行对一行，便于和反编译代码对照 |
| 构建 | Vite | 零配置，开发热更新，产物是纯静态文件 |
| 渲染 | **Canvas 2D**（实施时由 PixiJS 改定） | 角色改为全新矢量绘制，每帧实时画出来，任何缩放都清晰；48 个单位用 Canvas 2D 绰绰有余，还少一个依赖 |
| 界面 | DOM 覆盖层 + 原生 TS（约 30 行的 `h()` 工具，实施时由 Preact 改定） | 界面只有几个菜单和面板，不值得引入框架 |
| 测试 | Vitest（规格、不变量、统计、存读档）+ playwright-cli（端到端冒烟） | 都已在本机环境中可用 |
| 存储 | localStorage（实施时由 IndexedDB 改定），可导出/导入 `.json` 存档文件 | 单个存档约 30 KB，同步读写更简单 |

**实际依赖只有 4 个开发依赖**：vite、vitest、typescript、@types/node。运行时零依赖。
| 发布 | 首选浏览器/PWA（可离线）；后续可选 Tauri 打包为桌面程序 | 一套代码，免安装 |

不选 Godot/Unity：这款游戏的规模很小，而核心价值在于"逐行忠实移植"。TS 移植后可以直接和 AS 源码并排对照，长期维护成本最低。

## 2. 架构

```
src/
  core/            纯逻辑，无 DOM、无渲染、无真实时间 —— 可在 Node 中无头运行
    constants.ts   所有原版数值，每个都注明 AS 出处行号
    rng.ts         可设种子、可序列化的伪随机数（替代 Math.random）
    state.ts       GameState：纯数据，可直接 JSON 序列化
    mapgen.ts      ← 862/f1
    spawn.ts       ← 862/f2
    unit.ts        ← 862/f3 状态机（保留 start_sit / set_dir 等原名）
    ai/classic.ts  ← 862/f4，1:1 移植
    ai/commander.ts 改进 AI（只发出和玩家相同的指令）
    commands.ts    玩家/AI 指令以数据形式进入模拟（select 不进入，move/attack 进入）
    rules.ts       RuleSet：经典默认值 + 可选规则变体
    sim.ts         tick()：严格按原版顺序 people_action → com_orders → check_add_people
  render/          PixiJS：等距投影、深度排序、帧插值、小地图、特效
  ui/              Preact：标题、阵营选择、HUD、暂停/设置、存读档、结算
  i18n/            zh-CN.json（默认）、en.json
  save/            存档格式版本号 + 迁移函数
  audio/           WebAudio 封装，带音量控制
tools/
  extract-swf/     从用户本地 SWF 提取图集、帧表、音效 → assets/original/
tests/
  unit/ invariant/ stats/ replay/ e2e/
```

关键决策：

1. **逻辑与表现严格分离**。`core` 以固定 18 tick/s 运行，与原版逐帧一致；渲染层按显示器刷新率插值（例如 60/120 Hz），所以画面更顺滑，规则时序不变。
2. **确定性**。模拟只使用带种子的 RNG，因此"存档 = 状态快照 + RNG 状态"，"回放 = 种子 + 带 tick 号的指令序列"。读档后的走向和不读档完全一致，测试也能精确复现。
3. **"经典"与"改进"是同一引擎的不同配置**：
   - **体验选项**（镜头、选择保留、提示、存档、速度）：只影响操作和显示，**不改变规则**。
   - **规则变体**（改进 AI、智能寻路、公平地图）：会改变对局，界面上明确标注；"经典"预设下全部关闭，与原版行为完全一致。
4. **按函数移植**：TS 函数名、分支结构尽量与 AS 保持一致，每个函数顶部注释标出对应的 AS 文件和行号。以后任何人怀疑某处行为，都能在一分钟内找到原版代码对照。

## 3. 准确性保证与测试

| 层级 | 内容 | 例子 |
|---|---|---|
| 规格单元测试 | 把考证文档中每一条【确认】写成断言 | 出拳循环 15 帧；硬直 5；占领 300 坐帧；绿方无 ♠ 时每 250 帧刷 1 人；索敌半径 10；AI 发呆 400 帧才行动；人满时计数浪费 |
| 不变量（性质测试） | 随机种子跑几千局，每个 tick 检查 | 小格占用表与单位位置一致；每阵营 ≤12 人；hp ≤ mhp；淘汰后不再刷兵 |
| 统计对拍 | 大量无头对局，比较分布 | 1v1 胜率表（考证文档第 6 节）；地图特殊地块数量分布；四 AI 观战局的时长和胜者分布 |
| 原版神谕（Oracle） | 用 JPEXS 往原 SWF 注入 `trace` 日志，在 Ruffle 中无头运行，录制原版的真实事件序列（刷兵时刻、占领时刻、每次出拳和命中） | 和重制版的同类统计做分布检验；用来消除反编译偏差（U2） |
| 回放金样 | 固定种子 + 指令序列 → 最终状态哈希 | 防止重构时悄悄改变行为 |
| 视觉对照 | Playwright 在相同视口下截取重制版画面，与 Ruffle 原版截图并排比较 | 布局、配色、比例（不要求逐像素一致，因为地图是随机的） |
| 端到端 | 浏览器中走完完整流程 | 选阵营 → 框选 → 下令 → 存档 → 刷新页面 → 读档 → 状态一致 |

注：Flash 的 `Math.random` 无法复现，所以"准确"的定义是**规则、时序、概率分布一致**，而不是逐帧画面一致。

## 4. 美术复刻

| 阶段 | 做法 | 说明 |
|---|---|---|
| A 原样 | `tools/extract-swf` 从用户本地 SWF 读出 384 张角色位图、10 张地块位图和帧表（解决 U1），生成图集；棋盘、渐变背景、本部色块、小地图这些简单矢量元素用代码绘制，对照截图调色 | 观感与原版一致，是 MVP 的基础 |
| B 清晰版 | 离线用 xBRZ 类像素放大算法生成 2×/4× 图集，人工修边；加单位脚下软阴影、选中光圈、受击白闪、占领进度环；HiDPI 下界面文字使用矢量字体 | 保留原版构图和配色，只是变清楚、变"有反馈" |
| C 重绘（可选、长期） | 参照原风格新建低多边形学生模型，渲染成与原版相同的 4 方向 × 25 姿势布局，阵营色用调色板替换 | 帧表格式不变，可以直接替换素材包；**若要公开发布，必须走这一步** |

版权提醒：README 已注明原作不是开源作品。因此仓库**不提交**提取出的原版素材（写入 `.gitignore`），而是由提取工具在本地从你自己的 SWF 生成。私下游玩没有问题；公开发布需要使用 C 阶段的素材或取得授权。

## 5. 中文版

- 默认简体中文，设置中可切换英文。所有文字走 key → 词典，代码里不写死字符串。
- 建议译名（待你确认）：标题"校园战争 School Wars"；阵营"黑高 / 绿高 / 黄高 / 紫高"；"Level up!"→"升级！"；"X is annihilated."→"X 被全灭了"；"You win !!"→"你赢了！！"；"You lose..."→"你输了……"；"Quit this game"→"退出本局"；"Cancel"→"取消"；"Watch"→"观战"。
- 字体：标题和 HUD 用开源像素中文字体（如"缝合像素字体 Fusion Pixel"，OFL 授权）以贴近原作气质，正文用思源黑体，可在设置里切换。

## 6. "玩得舒服"清单（不增加系统复杂度）

**P0（随 MVP 之后第一批上线）**
- 存读档：3 个手动档位 + 自动存档（每 60 秒一次，以及退出时）；可导出/导入文件。
- 暂停（`Esc`/`P`）和 1×/2× 速度；原版的空格拖图保留。
- 选择保留：下令后选择不清空（设置里可切回原版行为）；右键下令（左键下令依然可用）；`Ctrl+A` 选中全部己方单位。
- 镜头：加边界；支持屏幕边缘滚动、WASD、滚轮缩放。
- 信息可见：地块上显示占领进度条；本部显示下一个新兵的倒计时；顶部显示四方人数和 ♠ 数；当有人成为"众矢之的"（top）时给出明显提示（原版的隐藏规则，玩家需要知道为什么突然被三家围攻）。
- 结算界面：胜负、用时、击杀数；可"同一张地图再来"或"新地图"。

**P1**
- AI 难度：经典 / 普通 / 困难（见第 7 节）。
- 智能寻路（规则变体，默认在"舒适"预设开启）：在小格网格上用 A* 绕开阻挡，减少原版"卡住后站着发呆"的情况。
- 公平地图（规则变体）：四角对称生成。
- 在标题画面明确提供"观战"入口（原版是隐藏按钮）。

**P2**
- 高清美术（第 4 节 B/C 阶段）、触屏操作、PWA 离线、桌面打包。

## 7. AI 改进方案

原则：**不作弊**（规则、信息、指令都与玩家相同）；**只替换战略层**（原版的 `com_orders`）；单位自动索敌、出拳、硬直、top 制衡等规则在所有难度下都一样，以保留原作手感。

`Commander` 每 9 tick（0.5 秒）为每个电脑阵营做一次决策，按分值从高到低：

1. **防守**：己方 ♠/♥ 或本部附近出现敌人时，调附近的空闲单位回防。
2. **撤退**：生命低于约 35% 且附近敌我数量处于劣势的单位，退到最近的己方 ♥ 或本部。
3. **经济**：以 2–3 人小队去占领 ♠，按"距离 + 威胁 + 收益"打分，不再单独去坐敌方本部（原版这样做没有收益）。
4. **集火**：主动进攻时优先打残血或落单的敌人；局部人数劣势时不进攻。
5. **反领先**：完整保留原版的 top 规则。

难度通过几个参数调节：反应间隔、发呆阈值（经典为 400 帧）、小队规模、是否启用撤退和集火。验收方法：固定种子跑 1000 局无头 AI 对战，要求"困难"对"经典"有明显胜率优势，同时检查对局时长分布，确保不会让玩家感到窒息（例如开局到第一次交战的时间不能过短）。
