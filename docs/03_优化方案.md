# 校园战争：在原版之上的优化方案

> 前提：当前版本已经忠实还原了原版（见 [01](01_原版机制考证.md)、[02](02_重构方案.md)）。这一阶段的目标是**把原版不合理的地方改好**，而不只是复现。
> 下文的"实测"数据均来自无头模拟，规则为原版、AI 为原版，可以复现。
> v0.2 起：四所学校改为人族 / 兽人 / 矮人 / 精灵高校，♠ / ♥ 改称营地 / 泉水，并加入 A* 寻路、进攻移动和撤退回血，见 [04](04_体验升级方案.md)。本文保留 v0.1 时的写法和数据。

## 0. 改动原则

1. **保留原版的灵魂**：四所学校、♠ 增援 / ♥ 回血、坐下占领、不良蹲、被打中会打断出拳（所以围殴很强）、闲着的学生会自动迎战、"众矢之的"的制衡思路、只有"移动 / 攻击"两种指令。
2. **只改让人觉得"不讲理、看不懂、没反馈、拖沓"的地方**。每项改动都要有数据或明确的理由，并且用无头模拟验收。
3. **不加新系统**：不加兵种、科技、资源。每条新规则都要能用一句话讲清楚。
4. **原版规则保留为一个选项**（推荐）。原版核心代码和 29 项测试都已经写好，保留成本很低，也方便对照新规则的效果。新规则作为默认。

## 1. 实测：原版的问题到底在哪

| 指标 | 实测结果 | 结论 |
|---|---|---|
| 40 分钟内分出胜负的对局比例 | **只有 43%**（150 局里有 86 局未结束，其中 66 局还剩 3 所学校） | **最大的问题**：对局拖沓，很难收尾 |
| "众矢之的"规则生效的时间 | 对局时长的 **65%** | 电脑只围攻领先者，导致弱者永远不会被消灭 |
| 四所学校最终获胜率（原版 AI 互打） | 黑曜 29%、金刚 15%、紫电 20.5%、**绿林 0%** | 平衡有问题，但要先修 AI 再调数值 |
| 电脑回家疗伤时的血量 | 中位数 60%；**28% 的回家发生在血量 ≥80% 时** | 原版只要"没满血"就回家，挨一下就撤 |
| 人满时浪费的增援 | 约占全部增援的 **10%** | 计数照扣、兵却没出，玩家看不到也无法理解 |
| 单兵移动指令的到达率 | 97.4% | 原版贪心寻路**基本够用**，A* 寻路不是当务之急 |
| 整队移动的到达率 | 96.4% 进入目标格，2.7% 停在相邻格 | 只需让多人分散落点，不必重写寻路 |
| 开局到第一次交战 | 中位 47 秒 | 节奏合理，改动后应保持在 40 秒以上 |

另外两处读代码即可确认的问题：走动中的单位不会被打中（对手只能干等它停下）；倒地的尸体在约 1.6 秒内仍然挡路。

## 2. 规则优化（核心）

### 2.1 让对局能收尾

| 改动 | 一句话规则 | 理由 |
|---|---|---|
| **攻占本部** | 敌人坐在你的本部上累计 600 帧（约 33 秒·人），本部就**沦陷**：停止增援、不能回血；你的学生坐回去 300 帧即可夺回 | 原版本部不可攻占，只能"杀到一个不剩"，而本部一直在出兵、回血。改动后进攻有明确目标，也让原版 AI 去坐敌方本部这个行为变得有意义 |
| **众矢之的只在 3 所以上学校存活时生效** | 只剩两家时不再有制衡 | 两家对决时制衡没有意义，只会拖时间 |
| **出局 = 本部沦陷且无人**（实施时新增） | 本部还在，人打光了也不出局，等增援翻盘 | 否则开局抢攻可在 4–5 分钟内直接灭掉一家，见 §9 |
| **众矢之的只影响电脑的选择**（实施时调整） | 新规则下学生自动迎战时不再受它限制；电脑指挥官对非领先者的进攻意愿打六折 | 单位层的限制让学生对眼前的敌人袖手旁观，造成大量僵局，见 §9 |
| **不保护濒死的学校** | 本部已沦陷的学校，不受"众矢之的"规则保护 | 原版中电脑只打领先者，弱者因此永远存活 |
| **增援不浪费** | 人满时，增援进度停在满格；一有空位立即补上 | 消除 10% 看不见的浪费 |
| **占领进度会衰减** | 没人继续占领 5 秒后，进度开始缓慢回退 | 原版中很久以前留下的进度永不消失，会导致"莫名其妙被占" |

验收标准：40 分钟未结束的对局 <5%；中位时长 15–25 分钟；四所学校的获胜率都在 18%–32% 之间。

### 2.2 战斗手感

| 改动 | 一句话规则 | 理由 |
|---|---|---|
| 自动迎战选最近的敌人 | 优先打正在打我方的敌人，其次是最近的、血少的 | 原版在 10 格内**随机**挑目标，会舍近求远 |
| 走动中也能被打中 | 相邻就能出拳 | 消除"走动无敌"，对手不再原地干等 |
| 执行移动指令的学生不会被拉走 | 被打时继续往目的地走（玩家意图优先）；空闲时照原版还手 | 撤退有代价，但指令可靠 |
| 自动追击有距离上限 | 自动迎战的追击离开原位超过 12 格就放弃并返回；玩家下达的攻击指令不受限 | 原版会追到天涯海角，导致丢掉正在占领的地块 |
| 倒地立即让出格子 | 尸体只保留画面效果，不再挡路 | 原版尸体挡路约 1.6 秒，造成堵塞 |
| 击倒有可感知的成长 | 每击倒 1 人：回复 30% 生命，生命上限 +2；头顶显示星级（每 3 次击倒一颗，最多 3 颗） | 原版只加 1 点上限，几乎感觉不到 |
| 命中率仍是 50%，但让它看得见 | 挥空时显示挥空动画和"闪"字 | 保留原版的随机性，同时让玩家看懂 |

### 2.3 平衡

先完成 2.1、2.2 和新 AI，再用锦标赛数据微调数值，不凭感觉改。最终数值见 §9。

## 3. AI 优化（"智商"）

**原则**：不作弊（与玩家拥有相同的规则、信息和指令）；只替换战略层（原版的 `com_orders`）；单位层的规则所有人共用。

**指挥官（Commander）**：每 0.5 秒为每所电脑学校决策一次，按优先级分配四类任务：

1. **防守**：己方地块或本部有敌人时，就近调兵回援，优先保住本部。
2. **撤退**：血量低于 35% 且局部处于劣势时，撤回最近的己方 ♥ 或本部（不再"掉一滴血就回家"）。
3. **扩张**：以 2–3 人小队去占 ♠，按"距离 + 威胁 + 收益"打分。
4. **进攻**：兵力占优时集结后推进，优先攻打已经虚弱的学校，或对方的本部。

**各校性格**（只是参数不同，让对手有辨识度）：绿林早期以人海扩张，金刚稳守反击，紫电偏好突袭，黑曜均衡发展。

**难度**：简单 / 普通 / 困难，通过反应间隔、小队协同程度、是否集火来区分。

**验收**：困难 AI 对原版 AI 胜率 >75%，普通 AI 约 60%；与玩家对局时，开局首次交战的中位时间不早于 40 秒，避免开局压迫感太强。

## 4. 操作优化

已经有的：现代操作方式、下令后保留选择、右键下令、Ctrl+A 全选、暂停与倍速。下面新增的都是即时战略游戏的通用习惯，不需要额外学习：

| 功能 | 做法 |
|---|---|
| 编队 | Ctrl+数字编组，按数字选中，双击数字时镜头跳过去 |
| 快速全选 | 双击某个学生，选中屏幕内全部己方学生 |
| **集结点** | 点击自己的本部后右键设置集结点，新兵自动前往（到达后坐下，顺便占领） |
| 整队落点分散 | 多人前往同一格时，自动分配不同的小格，人太多时溢出到相邻格 |
| **战报提醒** | 己方地块或本部遭到攻击、沦陷时，屏幕边缘出现提示，小地图闪烁；点击提示即跳过去 |
| 悬停信息 | 鼠标悬停在学生上显示生命和击倒数，悬停在地块上显示效果和占领进度 |

## 5. 画面与前端

| 改动 | 说明 |
|---|---|
| **势力比例条** | 顶部一条四色比例条，标出 40% 的"众矢之的"线，谁快被围攻一目了然 |
| 本部立体化 | 从平面徽章改为阵营色屋顶的小校门 / 教学楼；沦陷时插上敌方旗帜 |
| ♠ / ♥ 立体化 | 改为立在格子上的标牌，占领时有升旗动画；远处也能看清归属 |
| **体型反映属性** | 金刚更壮、紫电更精瘦、绿林更矮小，一眼看出"耐打"还是"能打" |
| 打击感 | 受击闪白、后仰位移、击倒时冒星星、挥空动画、占领时升旗配音效 |
| 色弱模式 | 地块和小地图上叠加校徽字或纹理，不只靠颜色区分 |
| 字体 | 打包开源像素风中文字体，用于标题和 HUD |
| 背景音乐（可选） | WebAudio 合成的轻量循环，默认音量低，可以关闭 |
| 渲染性能 | 棋盘和地块绘制到离屏缓存，只在发生变化时重绘；目标 1080p 下 60 fps、单帧绘制 <4 ms |

## 6. 架构调整

- **规则集**：`Rules` 增加 `classic` / `remake` 两套开关。核心代码在少数几个点上按开关分支；原版测试继续守护经典规则，新规则另写测试。
- **AI 模块**：指挥官只产出 `Command`，与玩家使用同一套指令接口；配套单元测试和锦标赛统计。
- **存档 v2**：新增规则集、编队、集结点、本部沦陷状态；v1 存档自动迁移为经典规则。
- **平衡工具**：`npm run sim -- --rules remake --ai hard` 输出胜率、时长、僵局率；50 局的快速版本作为回归门槛加进测试。
- **渲染分层**：静态缓存层、单位层、特效层、界面层。继续使用 Canvas 2D。

## 7. 实施顺序（每一步结束时都能玩、测试全部通过）

1. **O1 规则修正**：2.1 + 2.2。用模拟验收僵局率和对局时长。
2. **O2 新 AI**：指挥官 + 三档难度 + 各校性格。用锦标赛验收。
3. **O3 操作**：编队、集结点、战报提醒、悬停信息、整队落点。
4. **O4 画面**：势力条、本部和地块立体化、体型差异、打击感、字体。
5. **O5 平衡与打磨**：锦标赛调数值，再做一轮试玩修正。

## 8. 已拍板

1. 保留"经典规则"作为设置选项，默认用新规则。
2. 本部沦陷的后果：停止增援、不能回血，可以夺回。
3. 击倒成长：回血 30% + 生命上限 +2 + 星级显示。

## 9. 实施结果（2026-10-23）

O1–O4 已完成，O5 做了一轮数值与性能调整。共 54 项测试通过。经典规则逐帧还原：20 局 × 6000 帧的事件流指纹与改动前完全一致（新增的"挥空"事件除外）。

### 9.1 与方案不同的地方

| 方案 | 实际 | 原因 |
|---|---|---|
| 人打光即出局 | 本部沦陷**且**无人才出局 | 实测开局抢攻能在约 4.4 分钟时直接灭掉一家，对局还没展开就少一家 |
| 众矢之的限制所有单位 | 新规则下只作为电脑指挥官的偏好（对非领先者的进攻价值 ×0.6） | 单位层限制让学生对身边的敌人不还手，僵局率居高不下 |
| 只微调绿林生命 | 新规则阵营数值：生命 18/12/28/14、攻击 4/4/3/5、增援门槛不变（原版：20/10/25/15、4/2/3/5） | 绿林在加入"击倒回血"后成了别人的"血包"，原版 AI 下胜率 0%；仅加生命不够 |
| 棋盘画到离屏缓存 | 直接矢量绘制，背景改用 CSS 渐变 | 实测缓存再缩放贴图反而更慢（见 9.3） |
| 像素风字体、背景音乐 | **未做** | 不影响玩法，留待后续 |

难度的具体区别（只影响电脑的反应和协同，不给任何属性加成）：

| 难度 | 决策间隔 | 每次最多下令 | 局部优劣判断 / 集火 | 回防 ♠ ♥ | 撤退疗伤 | 攻本部门槛 |
|---|---|---|---|---|---|---|
| 简单 | 3 秒 | 1 | 否 | 否（只守本部） | 否 | ×1.4 |
| 普通 | 2 秒 | 2 | 否 | 否 | 是 | ×1 |
| 困难 | 0.5 秒 | 12 | 是 | 是 | 是 | ×0.9 |

另外：攻打敌方本部要等开局 5 分钟后，并且一旦开始就坚持到结束；开局第一分钟只在自家半场扩张。

### 9.2 锦标赛数据

`npm run sim -- <局数> 40 --rules remake ...`，40 分钟为上限。胜率依次为黑曜 / 绿林 / 金刚 / 紫电。

| 对局 | 结果 | 40 分钟未分胜负 | 中位时长 | 首次交战 |
|---|---|---|---|---|
| 普通 × 4（300 局） | 26.3 / 27.3 / 19.7 / 25.0 % | **1.7%** | 14.4 分钟 | 48 秒 |
| 困难 × 4（200 局） | 22.0 / 41.5 / 25.0 / 9.5 % | 2.0% | 12.2 分钟 | 46 秒 |
| 简单 × 4（200 局） | 9.0 / 33.0 / 30.5 / 13.5 % | 14.0% | 14.5 分钟 | 57 秒 |
| 原版规则、原版 AI（基线，150 局） | — | 57% | — | 47 秒 |

| 两种 AI 各控制两所学校（100 局，每局轮换） | 胜者属于前者的比例 |
|---|---|
| 困难 对 原版 AI | 98.9% |
| 普通 对 原版 AI | 77.8% |
| 简单 对 原版 AI | 27.4% |
| 困难 对 普通 | 86.9% |
| 普通 对 简单 | 78.9% |

**对照验收标准**：

- 达标：40 分钟未结束 <5%（普通 1.7%）；普通难度下四校胜率都在 18%–32%；首次交战不早于 40 秒；困难对原版 AI >75%。
- 中位时长 14.4 分钟，略短于 15–25 分钟的目标。节奏比原版紧凑，暂不拉长。
- **未达标**：普通对原版 AI 为 77.8%，高于目标的约 60%。三档难度的梯度清楚，原版 AI 大致介于简单和普通之间。
- **未达标**：困难难度下绿林 41.5%、紫电 9.5%。困难 AI 擅长集火，加上多人分散落点，人海一方收益最大。调整性格参数无效；把紫电生命提到 15 能让困难档均衡（27/26/26/19），但普通档的紫电会升到 39%。普通是默认难度，因此保留现有数值。
- 简单难度互打有 14% 的对局拖过 40 分钟：简单 AI 不会撤退，也很少攻本部。和玩家对局时不受影响，因为玩家会主动进攻。

调数值的工具：`node tools/balance.ts <局数> '<生命>' '<攻击>' '<增援门槛>' [难度]`。

### 9.3 渲染性能

测量环境：1080p，开局 5 分钟、场上 42 人。无头 Chrome 只有软件渲染（SwiftShader），所以数字偏悲观。

| | 单帧 JS 耗时 | 含光栅化 |
|---|---|---|
| 优化前（棋盘缓存按 3 倍生成，4620×2490） | — | 13.4 ms |
| 优化后 | 1.0 ms | 8.2 ms |

剩余开销主要是每个学生的矢量线条（每帧约 740 次描边）。带 GPU 的浏览器会快得多，但"单帧 <4 ms"在当前环境无法验证。如果以后需要，下一步是把学生的各个姿势预渲染成位图。
